# เชื่อมไฟล์เสียงของแคมเปญกับ Call ID

สถานะอัปเดต 15 ตุลาคม 2026: ตรวจพบว่า `GET /calls/{call_id}` ส่ง `conversation.key`, `conversation.agent_id` และ `conversation.linked_by` กลับมาแล้ว เว็บใช้ `linked_by: "exact"` เพื่อหาไฟล์เสียงของสายโดยตรง โดยตรวจ Call ID, Agent และรายการไฟล์ของบัญชีเดิมครบก่อนเปิดเสียง ไม่ใช้ลิงก์แบบ `time` ที่จับคู่จากเวลา การตรวจแคมเปญทดสอบจริงพบ exact link ทั้ง 6 สาย

Callback ด้านล่างเป็นทางเลือกสำหรับการส่งรหัสไฟล์จากบริการ ไม่จำเป็นสำหรับสายที่ API ประวัติส่ง exact link มาแล้ว จุดรับฝั่ง Voice Confirm พร้อมใช้งาน แต่ยังไม่ได้ยืนยันการส่ง callback จริงจาก Botnoi

## จุดรับข้อมูล

`POST https://voice-confirm-two.vercel.app/api/voice-recording`

Headers:

```text
Content-Type: application/json
Authorization: Bearer <RECORDING_CALLBACK_TOKEN>
```

ใช้คีย์รับเสียงที่กำหนดให้บัญชี Voice Bot นั้นโดยเฉพาะ คีย์นี้แยกจากคีย์รับผลตอบรับ, Session JWT และ Supabase key ผู้ดูแลเว็บจัดให้ผ่านช่องทางส่งคีย์ของการเชื่อมต่อ ไม่ใส่คีย์จริงในเอกสารนี้

## Payload

ส่ง JSON 4 ฟิลด์เท่านั้น:

```json
{
  "request_id": "22222222-2222-4222-8222-222222222222",
  "call_id": "oc_example",
  "agent_id": "agt_example",
  "file_path": "agt_example/2026-10-14_19-38-55_33333333-3333-4333-8333-333333333333_0.wav"
}
```

| ฟิลด์ | ที่มาของค่าจริง |
| --- | --- |
| `request_id` | `metadata.voice_request_id` ที่ Voice Confirm ส่งในคำขอโทรใหม่ หรือ `metadata.variables.vc_call_reference` ของสายเดิมที่เชื่อม Tool รับผล |
| `call_id` | Call ID จริงที่ระบบโทรของ Botnoi สร้างให้คำขอนี้ |
| `agent_id` | Agent ของคำขอโทรเดียวกัน |
| `file_path` | ไฟล์ที่ Botnoi ยืนยันว่าเป็นเสียงของ Call ID นี้ และเปิดได้ผ่าน `GET /logs/audio?file_path=...` |

ส่ง `.txt` จากรายการ log ได้ด้วย เว็บจะเปลี่ยนนามสกุลสุดท้ายเป็น `.wav` แต่ไฟล์เสียงต้องมีอยู่จริง ไม่รับ URL ดาวน์โหลด, เบอร์โทร, owner ID หรือรหัสแคมเปญจาก callback เว็บอ่านแคมเปญและเจ้าของจากคำขอโทรที่บันทึกไว้

ต้องส่งรหัสจากระบบโทร/บันทึกเสียงของ Botnoi ที่เห็นทั้ง Call ID และไฟล์ ไม่ให้บอทภาษาเดารหัสไฟล์จากเวลาหรือข้อความสนทนา

## ผลตอบกลับและการส่งซ้ำ

- HTTP 200: `{"received":true}` หมายถึงบันทึกรหัสเชื่อมแล้ว
- HTTP 200: `{"received":true,"duplicate":true}` หมายถึงเคยรับข้อมูลเดียวกันแล้ว
- HTTP 409 `Call not yet persisted` หรือ `Concurrent update`: ส่ง payload เดิมซ้ำด้วยระยะรอที่เพิ่มขึ้นจนสำเร็จ ห้ามสร้างคำขอโทรใหม่
- HTTP 503: ส่งข้อมูลเดิมซ้ำภายหลัง
- HTTP 409 กรณี Call ID ไม่ตรงหรือมีไฟล์อื่นเชื่อมอยู่แล้ว: ตรวจข้อมูลต้นทางก่อนส่งต่อ เว็บเก็บประวัติเดิมไว้
- HTTP 400/404: ตรวจรูปแบบ payload, Agent, วันของไฟล์ และรหัสคำขอ
- HTTP 401: ตรวจคีย์รับเสียงและบัญชี Voice Bot ที่เชื่อมอยู่

ปัจจุบันรองรับหนึ่งไฟล์เสียงต่อหนึ่งครั้งที่โทร ถ้าบริการแบ่งไฟล์หลายส่วน ให้ทีม Botnoi ยืนยันรูปแบบการส่งก่อนขยายสัญญานี้ ไม่แทนไฟล์เดิมด้วยส่วนถัดไป

## พฤติกรรมหลังได้รับข้อมูล

เว็บเก็บรหัสเชื่อมแยกต่อครั้งที่โทร เมื่อเปิดประวัติ จะตรวจบัญชี, แคมเปญ, Agent, Call ID และไฟล์ที่ยังอยู่ในรายการของบริการ ก่อนดึง WAV ผ่านเซิร์ฟเวอร์และปรับเสียงสำหรับฟังโดยอัตโนมัติ ผลตอบรับและประวัติครั้งอื่นยังอยู่ครบ

Callback บันทึกเฉพาะรหัสไฟล์ การตอบ `received:true` ไม่ได้หมายความว่าเว็บเก็บสำเนา WAV ถาวร ถ้าไฟล์ยังไม่พร้อมหรือถูกนำออกจากบริการ เว็บจะแจ้งข้อผิดพลาดตอนโหลดเสียง

## สิ่งที่ต้องให้ทีม Botnoi เปิดใช้

1. เก็บ `metadata.voice_request_id` คู่กับ Call ID ในคำขอโทร
2. เก็บความสัมพันธ์ระหว่าง Call ID กับไฟล์เสียงจริง
3. เมื่อ WAV พร้อม ส่ง callback ตามสัญญาข้างต้น พร้อมคีย์รับเสียงของบัญชี
4. เก็บคิวส่งซ้ำเมื่อเว็บตอบข้อผิดพลาดชั่วคราว
5. สำหรับสายเก่าที่มีรหัสอ้างอิงครบ ส่ง callback ย้อนหลังด้วยรหัสจากบันทึกจริง

Voice Confirm ยังไม่ได้ส่งคำขอเปิดใช้ไปยังทีม Botnoi และยังไม่ได้ยืนยันการส่ง callback จริงจากระบบของ Botnoi
